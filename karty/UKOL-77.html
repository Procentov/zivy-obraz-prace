Všechny kroky a důkazy

  1. Zajistit důkazy — odložit stranou soubory doložených běhů z C:/work/_vratny_runs/, aby je provoz nepřepsal - běží.
  2. Přečíst C:/work/mcp-vratny/server.py a popsat, jak se páruje run_id se souborem logu a s výsledkem, a co garantuje návratová hodnota volání - čeká.
  3. Postavit reprodukční test, který vadu vyvolá při N souběžných bězích (kritérium A1) - čeká.
  4. Změřit strop souběhu a číslo N, při kterém se záměna poprvé projeví (kritérium A2) - čeká.
  5. Rozhodnout, jestli příznaky A, B a C mají jednu příčinu, nebo víc (kritérium A3) - čeká.
  6. Ověřit frontu úkolů C:/work/fronta/bezec.py — táž příčina, nebo samostatná věc (kritérium A4) - čeká.
  7. Odevzdat návrh opravy s odhadem dopadu a rizika a prozatímní pravidlo pro asistenty do doby nasazení - čeká.
  8. Nasadit opravu a doložit ji záporným testem (kritérium A5) - čeká.

Akceptační kritéria

  • A1: Reprodukční test vyvolá záměnu logu aspoň jednou z pěti pokusů, doloženo dvěma run_id se shodným obsahem.
  • A2: Je změřeno, při kolika souběžných bězích se záměna začíná dít.
  • A3: Je doloženo, jestli příznaky A, B a C mají jednu příčinu, nebo víc.
  • A4: Je zodpovězeno, jestli fronta úkolů (C:/work/fronta/bezec.py) trpí toutéž příčinou.
  • A5: Existuje záporný test — důkaz, že po opravě se vada už nevyvolá. Report bez záporného testu se nepřebírá.
